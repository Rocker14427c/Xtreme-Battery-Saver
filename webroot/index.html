Screen-off CPU profile

The feature from ScreenOff CoresOff is available here through a v2 screen_off block. On an eight-core device, the equivalent manual configuration is:

version=2
delay=1

screen_off={
  disable_cores=cpu1 cpu2 cpu3 cpu4 cpu5 cpu6 cpu7
}

CPU0 is deliberately omitted. The module now checks writes and retries a refused online/offline change up to three times; a kernel can still reject hotplugging some cores.

Useful commands

  • su -c /data/adb/modules/XtremeBS/system/bin/XBSctl reload reloads the config without relying on a system mount.
  • su -c /data/adb/modules/XtremeBS/system/bin/XBSctl safe enters Safe Mode if a profile is too aggressive.
  • su -c 'cat /sys/devices/system/cpu/online' shows which CPUs are currently online.
  • After installation/update, reboot once so the service starts from the module directory.

How this UI works

KernelSU/ReSukiSU recognizes a module WebUI only when the module has webroot/index.html. This page uses the manager’s root bridge rather than the old localhost CGI server. On managers without a native WebUI button, use the module Action button for the legacy browser fallback.
